1Project idea and goal

The task is to connect a Java desktop app to an Arduino. They talk through a USB cable (a COM port). The result must be easy to see.

My project is a small temperature monitor:

  • The Arduino reads temperature and humidity from a sensor.
  • It sends the values to the Java app.
  • The Java app shows the values in real time.
  • The user can set a temperature limit.
  • The user can control an LED: ON, OFF or AUTO.
  • In AUTO mode the LED turns on when the temperature is above the limit. This is the visible result.

4Arduino part

The sketch is arduino/temperature_monitor.ino. It uses the DHT sensor library by Adafruit.

Main variables

VariableStart valueMeaning
limitTemp30The temperature limit in °C.
ledMode2 (AUTO)0 = OFF, 1 = ON, 2 = AUTO.
alarmState-11 = too hot, 0 = OK, −1 = not known yet.
lastTempNANThe last good temperature reading.
lineemptyCollects characters until a full command arrives.

So, if Java sends nothing, the Arduino still works alone: AUTO mode with a limit of 30 °C.

What each function does

  • setup() — starts Serial at 9600 baud, sets pin 8 as output, starts the sensor and sends STATUS:READY.
  • loop() — always checks for new commands. Every 2 seconds (using millis(), not delay()) it sends new readings. Because there is no delay(), the Arduino reacts to commands at once.
  • readSerial() — reads incoming characters one by one. It adds them to line. When it gets a newline (\n), the command is complete and goes to handleCommand(). It ignores \r, so Windows line endings also work.
  • handleCommand() — removes extra spaces, then checks the command:
    • LIMIT:<value> → saves the new limit.
    • LED:ON, LED:OFF, LED:AUTO → changes the LED mode.
    • For a good command it answers ACK: + the same command.
    • For anything else it answers ERR:BAD_COMMAND.
    • After a good command it calls checkAlarm(), so the LED updates at once.
  • sendReadings() — reads the sensor. If the reading fails, it sends ERR:SENSOR. If it works, it sends TEMP: with 1 decimal and HUM: with no decimals. Then it calls checkAlarm().
  • checkAlarm() — compares the last temperature with the limit. Alarm is 1 if the temperature is above the limit, else 0. It sends ALARM: only when the state changes, not every 2 seconds. Then it sets the LED:
    • ON mode → LED on.
    • OFF mode → LED off.
    • AUTO mode → LED on only when the alarm is 1.

DHT11 vs DHT22

For the real board with a DHT11, change one line:

DHT dht(DHT_PIN, DHT22);   // Wokwi
DHT dht(DHT_PIN, DHT11);   // real lab board

5Wokwi prototype

I built and tested the Arduino part in the Wokwi online simulator first. In Wokwi I can change the DHT22 temperature with a slider and watch the LED and the Serial Monitor.

What the Wokwi project shows:

  • An Arduino Uno, a DHT22 sensor, a red LED and a 220 Ω resistor, wired as in the wiring diagram.
  • The Serial Monitor prints STATUS:READY, then a new TEMP and HUM line every 2 seconds.
  • Clicking the DHT22 opens sliders for temperature and humidity. When the temperature goes above the limit, ALARM:1 appears and the LED lights up.
  • Commands like LIMIT:28 or LED:ON can be typed into the Serial Monitor to test the Arduino without Java.

6Java Swing application

The Java app is the user's control panel. It talks to the Arduino only through the text messages in the serial protocol.

Features

  • Connection: the user picks a COM port and connects. The app opens the port at 9600 baud.
  • Live values: big labels show the latest temperature (°C) and humidity (%).
  • Alarm indicator: shows if the temperature is above the limit.
  • Temperature limit: a text field and a button. The app sends LIMIT:<value>.
  • LED control: three buttons, ON, OFF and AUTO. They send LED:ON, LED:OFF and LED:AUTO.
  • Message log: shows the lines that come in, so the user can see ACK and ERR answers.

How the app handles each message

The app reads the serial data one line at a time. It splits each line at the first : into a name and a value. Then it reacts to the name:

Line from ArduinoWhat the app does
STATUS:READYShows that the Arduino is connected and ready.
TEMP:29.2Updates the temperature label.
HUM:45Updates the humidity label.
ALARM:1 / ALARM:0Turns the alarm indicator on or off.
ACK:...Confirms in the log that the command worked.
ERR:...Shows the error in the log.

Serial data arrives in the background. Swing labels must be changed on the Swing UI thread, so updates should go through SwingUtilities.invokeLater(). This keeps the window responsive.

How it looks

One window with three parts. At the top is the connection row: COM port list and Connect button. In the middle are the live temperature and humidity values and the alarm indicator. At the bottom are the limit field and the ON / OFF / AUTO buttons, with the message log below them.

7Communication

The app and the Arduino use USB Serial at 9600 baud. Every message is plain text and ends with a newline. So one line = one message. Each message has the form NAME:value.

8How to run

Arduino

  1. Open arduino/temperature_monitor.ino in the Arduino IDE.
  2. Install the DHT sensor library by Adafruit (Library Manager).
  3. For the real board, change DHT22 to DHT11.
  4. Connect the Uno by USB. Choose the board and the port. Upload.
  5. Optional check: open the Serial Monitor at 9600 baud. You should see STATUS:READY and then readings every 2 seconds. Close the Serial Monitor before you start the Java app — only one program can use the COM port.

Wokwi

  1. Open the Wokwi project.
  2. Press the green start button.
  3. Click the DHT22 and move the temperature slider above or below the limit.

Java app

  1. Close the Arduino Serial Monitor, so the COM port is free.
  2. Start the Java app.
  3. Choose the Arduino's COM port from the list and click Connect.
  4. Wait for STATUS:READY. Live values then appear every 2 seconds.
  5. Type a limit and send it. Then choose ON, OFF or AUTO for the LED.

10Problems and conclusion

Problems and solutions

  • Different sensors. Wokwi has a DHT22, the lab has a DHT11. The code stays the same. Only the sensor type in one line changes.
  • Waiting without blocking. delay(2000) would stop the Arduino from reading commands. The code uses millis(), so it reads commands and sends data at the same time.
  • Commands arrive in pieces. Serial data comes one character at a time. The Arduino collects characters until a newline. Only then does it handle the full command.
  • Windows line endings. Some programs send \r\n instead of \n. The code ignores \r and trims spaces, so both work.
  • Too many alarm messages. Sending ALARM every 2 seconds is noisy. The Arduino sends it only when the state changes.
  • Sensor errors. A DHT reading can fail. The Arduino then sends ERR:SENSOR instead of a wrong number.
  • Busy COM port. Only one program can open the port. The Arduino Serial Monitor must be closed before the Java app connects.

Known limitations

  • LIMIT: with text that is not a number (e.g. LIMIT:abc) becomes 0, because toFloat() returns 0. The Java app should only send valid numbers.
  • The alarm uses "greater than". If the temperature is exactly equal to the limit, the alarm stays off.

Conclusion

The project connects a Java Swing app and an Arduino with a simple text protocol over USB Serial. The Arduino reads the sensor every 2 seconds, sends the values, accepts commands and controls the LED. The Java app shows the values and sends the limit and LED commands.

The protocol uses one NAME:value message per line. This makes it easy to read, easy to test in the Serial Monitor, and easy to handle in Java. Every command gets an ACK or an ERR, so the user always knows if it worked. The LED gives a clear, visible result: in AUTO mode it lights up when the room is too warm.
