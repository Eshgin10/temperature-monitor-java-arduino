1Project idea and goal

The task is to connect a Java desktop app to an Arduino. They talk through a USB cable (a COM port). The result must be easy to see.

My project is a small temperature monitor:

  • The Arduino reads temperature and humidity from a sensor.
  • It sends the values to the Java app.
  • The Java app shows the values in real time.
  • The user can set a temperature limit.
  • The user can control an LED: ON, OFF or AUTO.
  • In AUTO mode the LED turns on when the temperature is above the limit. This is the visible result.

4Arduino part

The sketch is arduino/temperature_monitor.ino. It uses the DHT sensor library by Adafruit.

Main variables

VariableStart valueMeaning
limitTemp30The temperature limit in °C.
ledMode2 (AUTO)0 = OFF, 1 = ON, 2 = AUTO.
alarmState-11 = too hot, 0 = OK, −1 = not known yet.
lastTempNANThe last good temperature reading.
lineemptyCollects characters until a full command arrives.

So, if Java sends nothing, the Arduino still works alone: AUTO mode with a limit of 30 °C.

What each function does

  • setup() — starts Serial at 9600 baud, sets pin 8 as output, starts the sensor and sends STATUS:READY.
  • loop() — always checks for new commands. Every 2 seconds (using millis(), not delay()) it sends new readings. Because there is no delay(), the Arduino reacts to commands at once.
  • readSerial() — reads incoming characters one by one. It adds them to line. When it gets a newline (\n), the command is complete and goes to handleCommand(). It ignores \r, so Windows line endings also work.
  • handleCommand() — removes extra spaces, then checks the command:
    • LIMIT:<value> → saves the new limit.
    • LED:ON, LED:OFF, LED:AUTO → changes the LED mode.
    • For a good command it answers ACK: + the same command.
    • For anything else it answers ERR:BAD_COMMAND.
    • After a good command it calls checkAlarm(), so the LED updates at once.
  • sendReadings() — reads the sensor. If the reading fails, it sends ERR:SENSOR. If it works, it sends TEMP: with 1 decimal and HUM: with no decimals. Then it calls checkAlarm().
  • checkAlarm() — compares the last temperature with the limit. Alarm is 1 if the temperature is above the limit, else 0. It sends ALARM: only when the state changes, not every 2 seconds. Then it sets the LED:
    • ON mode → LED on.
    • OFF mode → LED off.
    • AUTO mode → LED on only when the alarm is 1.

DHT11 vs DHT22

For the real board with a DHT11, change one line:

DHT dht(DHT_PIN, DHT22);   // Wokwi
DHT dht(DHT_PIN, DHT11);   // real lab board

7Communication

The app and the Arduino use USB Serial at 9600 baud. Every message is plain text and ends with a newline. So one line = one message. Each message has the form NAME:value.

8How to run

Arduino

  1. Open arduino/temperature_monitor.ino in the Arduino IDE.
  2. Install the DHT sensor library by Adafruit (Library Manager).
  3. For the real board, change DHT22 to DHT11.
  4. Connect the Uno by USB. Choose the board and the port. Upload.
  5. Optional check: open the Serial Monitor at 9600 baud. You should see STATUS:READY and then readings every 2 seconds. Close the Serial Monitor before you start the Java app — only one program can use the COM port.

Wokwi

  1. Open the Wokwi project: [ADD WOKWI LINK]
  2. Press the green start button.
  3. Click the DHT22 and move the temperature slider above or below the limit.

10Problems and conclusion

Problems and how the code handles them

  • Different sensors. Wokwi has a DHT22, the lab has a DHT11. The code stays the same. Only the sensor type changes.
  • Waiting without blocking. delay(2000) would stop the Arduino from reading commands. The code uses millis(), so it can read commands and send data at the same time.
  • Too many alarm messages. Sending ALARM every 2 seconds is noisy. The Arduino sends it only when the state changes.

Known limitations

  • LIMIT: with text that is not a number (e.g. LIMIT:abc) becomes 0, because toFloat() returns 0. The Java app should only send valid numbers.
  • The alarm uses "greater than". If the temperature is exactly equal to the limit, the alarm stays off.
